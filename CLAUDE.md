# Project instructions

Read `CONVERSATION_HANDOFF.md` and `README_START_HERE.md` before changing code.

This project generates fastener-order and gasket-order Excel files from private Telegram text messages. Preserve the supplied Excel templates and the user's business rules. Make narrow changes and test HDG, SS316 and gasket output when generation logic changes.

## Non-negotiable business rules

- Projects are C3D1 or C3D2.
- `SS16` means `SS316`.
- Different projects or materials are sent as separate Telegram messages. Gaskets and fasteners are separate orders.
- Gasket orders start with `C3D1 Gasket` or `C3D2 Gasket` (`EPDM`, `EPDM Gasket` and `Gasket EPDM` are also accepted); the parser stores material `EPDM` and the file is `C3D1 EPDM Gasket Order.xlsx` from `templates/Gasket.xlsx`.
- Gasket items are written as `DN400 PN10 = 10`; thickness is 3 mm unless written (`DN400 PN10 5mm = 10`). Combine gaskets only when location, DN, PN and thickness match.
- Gaskets are EPDM with PN ratings only. Reject any other gasket material or ANSI Class rating with a message; do not add them (user decision, 15 September 2026).
- Gasket wording follows the gasket template, except that the template's typo `wth` is written as `with` at the user's request (2026-09-15): `SIZE: DN400 3MM THK Full-Face with Bolt Holes`, standard `BS 1154 Class Y3`, reinforcement `Single layers of fabric in accordance with BS EN 751` with bold `BS EN 751`, PN as a number, type `EPDM`, subject `RFQ for Gasket EPDM`, and `Document Required: Certificate for all items to be attached together with DO.`
- Keep every location/title as a separate Excel section.
- Combine nuts only when location and diameter match.
- Combine flat washers only when location, diameter and thickness match.
- Keep bolts separate by diameter and length.
- Keep stud rods separate by diameter and length.
- Do not add 5% unless the user explicitly asks for it. On the order forms (web and static page, 2026-11-12) the optional "Add 5% to all quantities" box does this: each entered quantity is rounded up (qty × 1.05) before consolidation; unticked by default and reset after each order.
- Include `Requester Name`; default to the Telegram sender's display name when omitted.
- Every bolt designation must start with `FULL THREADED HEXAGON BOLT`.
- Stud rods (HDG and SS316, user decision 2026-11-12) are written `FULL THREADED STUD ROD: M16, L=2000mm`; HDG stud rods use BS EN ISO 4190, G 8.8 (no longer refused). The fastener templates' subject reads `RFQ for Fastener (bolt, nut and washer)` (without "Steel Structure", user request 2026-11-12). The order forms label the buttons Hex bolt and Stud bolt.
- SS316: BS EN ISO 3506; bolts/washers/stud rods A4-70; nuts A4-80.
- HDG: bolts/nuts BS EN ISO 4190; washers BS 4320; strength G 8.8.
- Default washer thickness: M20 and below = 3 mm; M24 and above (M24–M46 and larger) = 4 mm. Washers above M20 thinner than 4 mm are refused (user rule, 2026-10-09).
- Preserve numeric Excel quantities and formulas. Unit prices remain blank; amount formulas activate after a price is entered.
- Every Monday at 09:00 Singapore time, send the administrator the previous Monday-to-Sunday order summary in Telegram: a message listing project, material, title and items, plus an Excel list.
- As soon as a colleague's order file is generated, send the administrator a copy of it with a caption naming the sender, project, material, requester, titles and items. The administrator's own orders are not copied. A failed copy is logged and recorded as `adminCopy` in the order's `delivery.json` without retry.
- `/sendemail` from any allowed user emails that chat's latest order file (or the file replied to) to the address in `email.json` through the Outlook profile on the host PC. Subject: `C3D1 HDG Fasteners · <requester> · <titles joined by "; ">` (`EPDM Gaskets` for gaskets); body: titles with items, requester, Telegram sender, time, attachment name.
- `/delete` from any allowed user (added 2026-10-12) removes that chat's latest order (or the order of the file replied to; the administrator replies to the copy of a colleague's file) from the records because its file is wrong: the order folder moves from `outputs/` to `deleted/` with a `deleted.json` note, so it leaves `/sendemail` and the weekly summary but is kept for the administrator. The administrator is emailed at once (`DELETED · <same subject as /sendemail>`, who deleted it, a warning if the order had already been emailed, the deleted file attached) and, if that email fails, notified in Telegram. Files already sent in Telegram are not removed from the chats. Steel forms and the weekly summaries already sent are not affected.
- Fastener orders may also arrive as an Excel file or a photo of a table (added 2026-09-30): sizes down the first column (`M24X210`, `M20x60 (Bolt only)`, `M16X2m`), `Bolt` / `Nut` / `Washer` (optionally `Washer (4mm)`) / `Stud rod` columns across the top; the caption must give the project and material on its first line and a `Title:`. A list table (added 2026-10-02) is also read: one worded item per row (`HEXAGON BOLT: M12 Gr 8.8, L=45mm`, `NUT: M12`, `WASHER: M12 X 3mm THKS`, Chinese translations in brackets ignored) with a `Qty` column (the `Total` one if several) and a top row such as `C3D2 | C3D2 WDL23 Cable Rack Type 1-4 | 5%`. Whatever the caption leaves out (even an empty caption) is taken from the table: project from the top row, material from the grade (`Gr 8.8` = HDG, `A4-70`/`A4-80` = SS316), title from the top row with the project prefix and percentage removed. A caption that disagrees with the table is refused; grades other than 8.8 are refused. Quantities are used as written; a `%` shown in the table is taken as already included and no 5% is added (the reply says so). Also read (added 2026-10-09): `Size | Grade | Qty` lists with the item word after the size (`M16 Nut`, grade column `SS A4-80`/`SS316L` gives the material), and `DESCRIPTION | SIZE | LENGTH (MM) | QTY` lists (`BS 4190 BOLT A4-70 | M27 | 145 | 40`; size and length are joined to the description). Also read (added 2026-11-06): numbered lists with size-first descriptions (`17 | M30 x 190mm Hexagon Bolt | 48 | Nos`, `Hex Nut M30`, `Flat Washer M30 (31 ID x 56 OD x 4 thk)`): a cell naming several item types (`Bolt, Nut & Washer A4-70`) is a section label, not a column heading, and gives the material; a Qty heading left of the description (OCR merged the heading row) is ignored in favour of the last number after the description; a row merged into one cell ending in `20 Nos` is split. `Requestor:` is accepted as `Requester:`. An OCR title with no spaces is ignored, so the caption must give `Title:`. The OCR engine runs with the angle classifier off (it flipped `90` to `06`). `table.mjs` turns the grid into the text order format and everything else (parsing, consolidation, template, admin copy, `/sendemail`) is unchanged. Photos go through the PDF bot's offline OCR (`image2xlsx.py`, path in `table.json`); the bot always replies with the text it read so the sender can check the quantities. A material named in the table must match the caption. Gasket lists are accepted since 2026-10-09 (user request): a first line naming the project and gasket/EPDM (e.g. `C3D2 Fibre Reinforced EPDM 3mm Thk Gasket for WDL21 Dampers`; thickness from the header, Title = the text after "for" unless a `Title:` line is given; other materials are refused) and one row per size (`1 DN100 PN10 106`), typed as a message, as a photo/Excel caption (used as typed, no OCR), or as a photo/Excel table. `table.mjs` `gasketOrderText` turns them into `DN100 PN10 3mm = 106` lines; rows without PN (e.g. ANSI Class) are refused. Since 2026-11-06 a table may give Qty and PN in their own columns (`Item | Description | Qty | PN`, PN as a bare `10`), and a `Gasket 3mm EPDM` row gives the thickness when the caption does not. Gasket photos are first read by position (`ocr_lines.py` beside bot.mjs, using the PDF bot's levelling and OCR; `table.mjs` `imageToLines` / `linesToGrid`): words go to the Qty / PN heading above them, and a heading column left empty on a DN row is re-read from a close crop, because the page OCR skips small single figures and the cell reader lost the columns of a cropped screenshot. The positioned lines are saved as `ocr-lines.json` in the order folder; the cell reader is the fallback.
- Steel-work Word forms (added 2026-09-21): a message with a `Project Forms: C3D1|C3D2` line (or first line `C3D1 Steel Form`) plus Our Reference Number, Current Date (`today` = Singapore date), Description of Steel Work (multi-line, line breaks kept), Batch Number, Estimated Tonnage and Required Steel Delivery Date (day/month/year, or a label such as `Type3-20/9/26`) generates the written notification and request form with the steel-forms handoff's own `update_steel_forms.py` and approved templates, never with `--compact-request-layout`. The rules of that handoff's CLAUDE.md apply (its root is in `steel.json`). Every field is required; the reference must belong to the chosen project. A repeated reference is saved as `_rev2`, `_rev3` … and never overwrites an earlier submission. Files are sent only after the field check passes; the Word layout check (page count, signature names on page 1, text-box overflow) is reported in the caption and, when Word is unavailable, the caption says the layout was not visually checked.

## Security and privacy

- Never print, copy, log, export or request the Telegram bot token.
- Never include `token.dpapi`, `config.json`, `state.json`, `email.json`, `steel.json`, `table.json`, order archives (`outputs/`, `deleted/`, `steel/`), weekly summaries (`summaries/`), logs or Telegram IDs in a handoff or repository.
- Treat requester names and order content as private business data.
- The BotFather token appeared in a screenshot during setup. The user was advised to revoke it. Verify only whether the live bot works; do not ask the user to paste the token into chat.
- Continue restricting the bot to private chats and an allowlist unless the user explicitly changes that policy.

## Current implementation

- `parser.mjs`: validates text orders and consolidates matching items; `fastenerItem` and `gasketItem` read one item line each.
- `excel.mjs`: creates one workbook from the applicable template. It first turns the template's shared formulas into their cached values, because Excel re-applies a shared formula over any quantity or total later written into its range. `generate` fills the HDG/SS316 fastener templates (quantity F, unit price H, amount I); `generateGasket` fills `templates/Gasket.xlsx` (Size, Standard, Reinforcement, PN, Type, Total Qty, Remarks, Unit Price, Amount in B–J) and writes the template's rich-text reinforcement cell onto every item row through the workbook proto, because `copyTo` carries neither formats nor rich text. Both share `open` (template, sheet name, header cells) and `save` (recalculation, checks, preview, export).
- `bot.mjs`: Telegram long polling, private-chat access control, delivery status and file upload. It copies each colleague's order file to the administrator, sends the weekly summary (catching up on weeks missed while the host was off) and answers the administrator's `/summary` with the week so far.
- `summary.mjs`: selects each week's orders and builds the summary message, the administrator's order-copy caption and the Excel list.
- `mail.mjs` and `SendMail.ps1`: `/sendemail` subject and body, lookup of the order to email, and sending through classic Outlook COM (the script reports `sent` when the message leaves the Outbox, `queued` if Outlook has not connected yet). Since 2026-10-07 `New-Object -ComObject Outlook.Application` fails with 0x80080005 on the host (an Outlook started by COM never registers), so the script attaches to a running Outlook with `GetActiveObject`, or starts `OUTLOOK.EXE` minimized and attaches once it registers. Outlook registers for attaching only after its window has been active and lost focus (KB 238610), so a minimized start never registered (2026-10-09); while waiting, the script activates the Outlook window briefly and minimizes it again every 5 s. `SendMail.ps1 -Probe` checks the connection without sending. The recipient is read from `email.json` (`{"to": "..."}`) on each command.
- `table.mjs`: Excel/photo table orders — `readGrid` (first sheet via artifact-tool), `gridToOrderLines`, `orderTextFromTable` (caption checks), `imageToXlsx` (spawns the PDF bot's `image2xlsx.py` from `table.json`). bot.mjs `handleAttachment` downloads the file into the order's `outputs/<chat>_<msg>/` folder (`source.*`, `table.xlsx`) and then uses the shared `startJob`/`deliverOrder` path.
- `steel.mjs`, `steel_verify.py` and `RenderDocx.ps1`: steel-work forms. `steel.json` (`{"root": "<steel handoff folder>", "python": [candidates]}`) names the handoff whose `outputs/update_steel_forms.py` and templates are used; submissions land in that folder's `outputs/` as `submission_details_<PROJ>_STPR_<NNN>[_revN].json` and `<PROJ>_STPR_<NNN>_Output[_revN]/` (with a `preview/` PDF pair). `steel_verify.py` checks every field where the template holds it (twice in the request form, which keeps a text box and its fallback) and that all other template text, including every signature line, survives. `RenderDocx.ps1` renders copies with Word COM and reports pages, page-1 body text and text-box overflow. Bot-side records live in `steel/<chat>_<message>/`; these submissions are not part of the weekly order summary.
- `web.mjs`, `web.html`, `StartWeb.ps1`/`StopWeb.ps1` (added 2026-11-12): web order form for colleagues on the office network, a separate process from the bot. The page (project, material, titles, item rows with size pickers) posts JSON; `orderText` turns it into the text order format and `parseOrder` / `generate` / `sendMail` do the rest, so no business rule lives in the page. `/api/preview` returns what the Excel will list; `/api/order` (after Confirm) generates the file into `outputs/web_<time>_<random>/` (with `request.json`, `delivery.json`, so it appears in the weekly summary), emails it to the `email.json` address at once (same subject as `/sendemail`, body says `web order form`) and returns a download link. `web.json` (`{"port": 8080, "code": ""}`, private like `config.json`): no access code since 2026-11-12 at the user's request (the link is shared directly with colleagues); a non-empty `code` brings the access-code field back. At most 30 orders per hour are accepted, because every order emails the administrator. Web orders are not reachable by Telegram `/sendemail` or `/delete`. Outside access (user chose the free, no-account route on 2026-11-12; Tailscale's free plan is non-commercial): when `cloudflared.exe` (not in the repository) sits beside `web.mjs`, the server runs a Cloudflare quick tunnel, restarts it when it stops and keeps the current random `https://….trycloudflare.com` address in `web-url.json` (private, removed while the tunnel is down). `/web` in the bot, from any allowed user, replies with that address (and the access code, if one is set). Permanent link (2026-11-12, user chose their GitHub account): `https://taiwankoo88.github.io/twrp-telegram-bots/` is the `gh-pages` branch of the repository, holding `index.html` (a copy of `web-link.html`) and `url.json`; a clone of that branch lives in the live folder as `pages/`. `web.json` `pages` / `git` / `link` name the clone, git.exe and the link; each new tunnel address is committed and pushed to `gh-pages` by `web.mjs` `publish` (Git Credential Manager, retried 6 times), and the form page and `/web` show the permanent link. Never push anything else to `gh-pages`. Wrong-code lockout counts the caller named by the tunnel (`CF-Connecting-IP`), not loopback.
- Static order page (added 2026-11-12, so orders work while the host PC is off; user decision): `site/index.html` + `site/config.js` + `site/base/*.xlsx`, published with `parser.mjs`, `items.mjs` and `xlsx.mjs` on the repository's `gh-pages` branch (clone in the live folder's `pages/`; test address `…/twrp-telegram-bots/form/`). Everything runs in the browser: `orderText` + `parseOrder` check the order, `xlsx.mjs` `buildWorkbook` writes the workbook from a base file that `excel.mjs` itself generated (`gen-base.mjs` makes the six bases, one per project and material) by rewriting the sheet rows with the base's own styles, and the file is posted to a Google Apps Script web app (`google-apps-script.gs`, deployed by the user in their Google account; its URL goes in `site/config.js` `MAIL_URL`) that emails it to the administrator and lists the items in a Google Sheet. These orders never reach the host PC, so they are not in `outputs/` or the weekly summary. `items.mjs` holds the rules shared with the browser (`describeItem`, `literal`, `sectionLines`, `mailSubject`, `orderText`) and must stay free of Node imports; `excel.mjs`, `summary.mjs` and `mail.mjs` re-export them. After any change to `excel.mjs`, the templates or `xlsx.mjs`: run `gen-base.mjs`, then `test-xlsx.mjs` (compares the page's workbook with the bot's cell by cell; beyond row 101 only the note row's style numbers may differ), then copy `site/*`, `parser.mjs`, `items.mjs`, `xlsx.mjs` into the `pages/` clone and push `gh-pages`.
- `startup.mjs`: retries transient Telegram startup failures.
- `Setup.ps1`: validates the bot with Telegram and saves its token using Windows DPAPI.
- `Start.ps1`, `Stop.ps1`, `Restart.ps1`: local lifecycle controls.
- `test.mjs`, `verify_export.py`: parser, workbook and saved XLSX checks. `verify_export.py` fails on any formula the generator did not write.

The portable package excludes `node_modules`. The live installation uses a Windows junction to Codex's bundled `@oai/artifact-tool`. If moving to another machine, replace this dependency deliberately or port Excel generation to a supported library while matching the templates and output exactly.

After code changes, run syntax and relevant tests. For generation changes, inspect and render all three template variants (HDG, SS316, Gasket), and open the saved files in Excel: artifact-tool's own recalculation and preview can disagree with Excel. `test.mjs` exits with code 0xC0000409 after rendering even when every check passes, so judge it by its printed output. Restart the live bot only after tests pass.
